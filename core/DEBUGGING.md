# 排障与根因归因

本方法补充调查质量，不改变协作模式、权限或 `REVIEW_PRINCIPLES.md` R6 分诊。
先从实际加载的机制源定位本文件；不要假设业务仓库有 `core/`。

## 建立可检查的事实

记录准确症状、预期行为、发生环境与版本，以及已经知道的事实。
区分观察结果、用户猜测与待验证解释；先确认调查针对的是同一个症状。
有执行能力时，用最小、可重复的探针建立失败信号，逐步去掉无关条件。
导入失败、依赖缺失等无关错误不能充当原故障复现。
无法复现时仍可只读分析与收集证据，但要明确假设和缺口，不能称根因已证实或问题已修复。

## 用对照缩小解释

对每个重要假设写出可证伪预测：若解释成立，应观察到什么，什么结果会推翻它。
优先选择能区分候选解释的对照；控制会影响判断的环境、输入与版本差异。
按预期信息量安排下一次探针，不凑固定数量的假设，也不新增审批步骤。
使用现有日志、最小样例和可控环境；重复同一个无信息增量的操作不是调查进展。

在下根因结论前，主动找当前解释无法解释的已知事实。
找得到就保留该事实并说明解释不完整；可以先止血，但不能据此结案。
找不到也须写明证据范围，不把有限样本推成全称结论。
记录排除其他假设的判据：哪组观察能区分它们，为什么这组差异支持排除。
已有真实样本时，验证判据两侧的样本，不能只凭直觉相信某个阈值。

## 修复与交付

修复后沿原故障路径复跑，并按 [测试与验证](TESTING.md) 检查受影响的既有行为。
区分止血措施、根因修复和仍待解释的事实；探针被拒或未执行须如实标注。
清理本任务创建的临时探针，保留需要复核的证据；不清理他人的工作。
生产观测、真实数据操作和高负载压测遵守已有授权与资源边界，不能为了复现扩大访问。

产物可是一份简短报告，包含结论、支持与反证、排除判据、实际验证和未覆盖范围。
需持久记录时使用项目已有权威文档；没有约定则留在本任务证据记录，
不要求每个项目建立统一目录。
