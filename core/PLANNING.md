# 需求澄清、方案与任务拆分

本方法供负责规划的主模型使用，补充规划质量，不授予实施权限。
用户明确要求规划、需求尚不清楚、新功能或跨模块工作需要先定范围、编制接力方案时读取。
从已加载的共享入口或适配源定位本文件，不从业务 cwd 猜路径。
明确的一两处小改、简单答疑和例行操作，不因此增加规划文件或访谈。
直接规划、solo 与接力均可使用；模式、评审判定与轮次仍按既有权威执行。
独立实施者执行已定稿方案，不因本方法重新规划或递归启动接力。

## 先查事实，再澄清取舍

先读项目入口、当前状态、相关实现与测试，分清已知事实、用户目标与约束、待验证假设。
已有答案直接沿用；能从仓库或现有证据查到的事实自行调查。
部署规模未声明时写明待核对，不把其他项目或全局旧假设当作当前项目事实。
只将无法合理推断、且会改变目标、产品取舍、边界或权限的问题交给用户。
说明推荐选项及其影响；依赖答案的工作等待，其余独立工作可以继续。
不做穷尽访谈或形式化确认；已有授权内的可逆内部选择自行决定。
产品差异与授权仍遵守项目及适配层规则，不新增确认门槛。

涉及模块职责、接口、依赖边界或跨调用方业务规则重复时，
负责规划的主模型按需读取同源 [DESIGN.md](DESIGN.md)，将关键契约写入方案。
独立实施者按定稿契约实现，不因此重新设计。

## 写到足够执行和验收

按任务大小保留必要信息，避免把小任务扩成完整规格工程：

- 目标与非目标，当前行为及预期变化。
- 检索得到的影响范围、明确文件清单，项目要求的行数与门禁。
- 关键接口、数据约束、兼容或回滚方式。
- 从需求与独立样例定义的可观察验收，以及未覆盖边界。

原始需求与模型推断分开；request 纪律遵守 `REVIEW_PRINCIPLES.md` R2，
不能用方案摘要代替用户原文。行为验证遵守 [TESTING.md](TESTING.md)。

## 必要时拆成可验证的行为片段

优先按完整可观察行为切片，不机械地先做所有数据库、再做所有 API、最后做所有 UI。
每片只列必要目标、真实前置依赖、写文件集合与验证方式；有依赖的按顺序执行。
跨任务或代理并行前核对共享文件和状态的所有权，重叠未解决不得并发写。
不能凭任务名字判断独立。本方法不自动创建分支、worktree、工单或代理；
只有既有流程允许并行时，才以依赖和写集合判断能否并行。
宽范围机械迁移若无法分片保持可用，可先兼容扩展、逐步迁移、最后收缩，
并明确整体集成验证点，不强迫所有改动采用同一种拆分形状。

## 出稿前初步验证

单方案和双方案共用，适用于 Claude 或 Codex 主导规划。只验证决定行为对错的关键设计点，
例如进程、管道与信号时序，字符串、正则与路径匹配，退出码与状态判定，配置优先级与续接路径，
以及跨文件调用契约。明确的一两处小改不增加流程。

1. **核对仓库事实**。对照源码核实文件、行数、函数、常量与现有行为。
2. **核对运行证据**。从 manifest 或日志读取模型、深度、耗时与调用次数，区分请求值、实际值和事件条数。
3. **反例走查**。主动构造会让设计失效的输入或时序。
4. **最小探针**。有执行能力时，在暂存区或临时目录运行几行代码或建临时仓库，单个探针控制在几分钟内。
   真实工作树和用户配置保持只读，探针不调用外部模型、不联网安装。无执行能力时（如 AGY plan 模式），
   只读代码并手推反例，标为「待运行验证」，不得声称运行过命令或测试（R10）。
   双方案规划中，若副方案模型处于无命令执行的只读模式，主模型可将出稿前已实测的**纯客观只读环境探针事实**
   经 `--instructions` 传给副方案模型。只摘录所需的版本号、命令选项、目录结构与退出状态，仓库物理与逻辑
   绝对路径替换为 `<REPO_ROOT>`，任何凭证或含凭证 URL 按 R2 替换为 `<已脱敏>`。严禁混入主模型的设计方案、
   取舍倾向或草稿。
5. **对照需求原文排查遗漏**。核对触发入口，默认、禁用与覆盖的优先级，失败和中断分支，续接与产物读取路径。

结论只写到证据能支持的程度。工具已声明时只记录声明，能否调用须有运行证据。替换路径后，
须检验引用能否定位才可声称修复。方案末尾记录「设计点 → 手段与依据（文件行号或探针） → 结果
（已确认、已证伪并改正、待运行验证及最小样本）」。被证伪的设计先改正再写入送审稿。

这一步防止 2026-11-20 方案综合误采未验证时序和正则、草稿遗漏分支及运行证据误报。
见 [规则由来](DESIGN_RATIONALE.md#2026-11-20-规划初步验证综合复核与-agy-暂存路径)。
验证限于方案主张，避免为此写实现原型。实施授权、交叉评审轮次与分诊仍按既有流程执行。

## 收束与变化处理

范围和关键决策足够清楚、各片可执行可验证时，结束规划。
仍有阻塞则说明未知项及其影响，不假装已经全部敲定。
实施中新事实改变范围时，回到既有变更及评审纪律，不由本方法另开评审循环。
记录写回项目已有状态、决策或方案位置；无约定时使用本次任务记录，
不要求每个新项目创建统一文档目录或执行 setup。
