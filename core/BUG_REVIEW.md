# 通用问题复核

本能力只在调用方显式要求时使用，业务采集、分析与补查由上层负责，不改变全局默认路由。
复核是第二意见，不授予采集、修复、实施、部署或发布权限。R1/R7/R10 继续适用；
诊断不用 R4/R5/R8 的改动检查模板。不得用 R6 的“登记即关闭”消除影响根因的证据缺口；
原 plan/diff 的 R6 含义不变。

调用方保存用户原话与预期为 problem_file，初步分析另存 analysis_file；不得把推断伪装成用户要求。
分析应列候选解释、证据 id、排除依据、反证和未验证项。只声明准备送审的 UTF-8 文本；
证据逐项标明 id、来源、原位置/时段、raw_excerpt 或 derived、范围与遗漏。derived 不是原始材料。
完整字段与命令见 docs/BUG_REVIEW.md。来源哈希只证明送审字节，不证明远端日志真伪。
无证据可复核缺口，但不得声称根因已证实。

先冻结全部声明材料，再以新进程完成 independent → review 两阶段。第一阶段不提供分析文件、
路径或哈希，独立列解释和验证判据；“盲”不保证调用方选择证据无倾向。
第二阶段完整读取问题、环境、证据、领域检查、限制、分析及原样独立清单。
不能省读分块，不能用检索代替完整读取，不能执行探针、next_check 或写业务文件。
任何失败保留日志与 failed 状态；无自动重试、换模型、降级或格式修复调用。
prepare-only 不读凭证、不启动模型，只准备第一阶段；第二阶段必须等待真实独立输出。

completed 只表示协议校验完成；supported 只表示已读材料支持，不等同生产实证、根因成立或已修复。
模型身份按现有运行时证据准确限定；requested_only 不是已证实实际模型。
调用方核对主模型与评审模型；同模型或未知身份不得宣称跨模型。
工具协议限制不是操作系统级文件或凭证隔离。

调用方逐条裁决“采纳 / 待验证 / 驳回”，给出证据，不遗漏原意见；可持久保存 adjudication.md。
复核方只提出补证请求，上层在已有授权内取证，补查本身不自动重审。
默认一轮；重要新事实或根因发生实质变化才启动第二轮，最多两轮。
调用方持有 task_id、递增 revision、材料与裁决，第二轮必须传首轮 completed 输出为 --previous。
入口核验任务、轮次、前轮哈希并独占声明第二轮谱系；这是本机单任务约定，
不声称防止复制目录、伪造状态或故意改 task_id 的全局绕过。
失败或已用过的第二轮不能由入口自动重试；prepare-only 不占用谱系。
缺材料或第二轮仍有分歧时列出未知项，禁止称根因已证实。

人工确认修复前停在报告。获授权后，把结论、证据、缺口和原故障验证条件交给既有方案评审流程，
核对代码版本与环境变化；问题复核不能代替修复方案评审或实施验收。
保留证据，不自动修改上层业务 skill 的“已验证模式”。
