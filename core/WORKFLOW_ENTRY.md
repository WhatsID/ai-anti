# 用户级工作流入口

这是 Claude Code 与 Codex 共用的常驻分流约定，不是硬执行状态机。
先读项目入口及任务对应的权威文档；入口缺失可探索，不因此拒绝小任务。
保护已有未提交改动；遵守工具原生指令优先级、项目规则和用户授权。
业务参数以项目为准。全局入口不授予实施、提交、推送、部署或真实数据写入权限。
仅获调查或计划授权时，停在该边界。区分事实、推断和未验证项，不把安装检查当作模型遵循证据。

简单答疑直接回答；小任务直接做。命中接力时才读取适配层与
`REVIEW_PRINCIPLES.md` 的所需规则；外部 CLI 调用前读取 `CLI_DISCIPLINE.md`。
被委派的实施者或评审者遵守本次边界，不递归自动启动接力。

## 按需加载共享方法

负责规划的主模型在用户要求规划、需求需要澄清、新功能或跨模块工作需先定范围、
编制接力方案时读取同源 [PLANNING.md](PLANNING.md)。明确小改不因此增加完整规划。
新增或调整模块职责、接口、依赖边界，或跨调用方明显重复业务规则时，
负责设计或规划的主模型读取同源 [DESIGN.md](DESIGN.md)；独立实施者按定稿契约实现，
不因此重新设计。文案、小样式和局部修复不因此加载完整设计流程。
排障调查或根因归因时读取同源 [DEBUGGING.md](DEBUGGING.md)；行为修改、实施验证
或验收时读取 [TESTING.md](TESTING.md)。从实际加载的本文件解析路径，不从业务 cwd 猜。
简单答疑或纯文档编辑不必加载不适用的方法；solo 与直接做同样按适用性读取。
用户要求复盘、维护规则，或当前任务出现有证据的重复协作问题时，
负责复盘的主模型读取同源 [RETRO.md](RETRO.md)。先按证据分类，再选最小改进；
普通成功任务不自动复盘，独立实施者不递归复盘；诊断不自动授权修改跨项目规则。
必要方法源缺失时报告加载缺口，不能伪称已遵循。
这些方法补充调查与验证质量，不改变模式、权限、接力轮次或评审分诊；
评审裁决仍以 `REVIEW_PRINCIPLES.md` R6 为准。

先用 `git rev-parse --show-toplevel` 定位项目根；非 Git 目录才回落当前目录。
模式文件相对项目根定位，不从启动子目录猜测。

新项目缺入口或参数时沿用已有平台默认，不虚构项目状态或风险配置。
完整接力需要 Git 当前 `HEAD^{commit}` 的精确提交基线；任意分支或 detached HEAD 均可。
无提交或非 Git 目录不通过未授权初始化、提交、建分支或切分支凑前提。
需要时可用 `install.sh --status --project DIR` 只读查看，不要求每项任务必跑。

## 协作模式开关

- 模式优先级：用户当前消息里的明确指令（「直接改」「走流程」「跳过评审」）> 仓库根 `.claude/relay-mode.local`（单行 `solo` / `auto` / `rules` / `force`）> 用户级 `~/.config/ai-anti/config.json` 的 `relay.default_mode` > 内置 `rules`。Claude Code 可用 `/relay-mode` 查看来源或切换项目模式；当次指令仅对当次任务生效。项目文件存在但不可读或无效、全局 JSON 损坏、配置根对象或 relay 节类型无效、或模式类型/值无效时停止并明确报错，不静默回落。菜单栏修改的是全局默认，不能覆盖已有项目模式。
- `solo`：所有任务由主模型独立完成——不调用评审通道、不派 implementer，高风险触发器也不例外（切入 solo 即视为用户对其间任务概括授权跳过评审）；涉及大任务或高风险的汇报须标注「未经交叉评审」。
- `auto`：是否走流程由主模型自行判定，下方规模标准仅作参考；高风险触发器仍强制走流程。
- `rules`（默认）：按下方「任务规模判定」执行——大任务与高风险任务走接力流程，其余直接做。
- `force`：所有实质性任务一律走接力流程；简单问答、排查咨询类仍直接回答。

仅接受 `solo`、`auto`、`rules`、`force`；旧值 `required` 无效，不作兼容；模式错误须列出合法值 solo/auto/rules/force。

## 任务规模判定（rules 档规则，auto 档作参考；由你判定，不要问用户）

- **直接做**（默认）：单文件 bug 修复、文案/样式/配置调整、指向明确的一两处小改动、排查/答疑、例行的数据更新与管线运维操作。
- **走接力流程**，满足任一：新功能或新模块；预计改动 ≥3 个会改变运行行为的**生产**文件（源码、脚本、SQL、Dockerfile、CI、运行配置计入；**测试文件不计入门槛**——写测试是义务，不该成为把小改动推进重流程的理由；纯文档、数据产物、生成文件同样不计）；跨两个及以上顶层子系统的改动（**项目覆写项**）；需求含糊需要先定方案再动手。
- **高风险触发器**（不论改动几个文件，一律走流程）：**接力流程与评审通道自身的配置**（本文件的流程各节、`adapters/claude-code/commands/`、`adapters/claude-code/agents/`、`core/`、本仓库 `install.sh`，以及各项目的 `.claude/settings*.json`——守门机制不得比它守的东西更好改）。此外由项目按自身风险面追加**业务高风险触发器清单**（**项目覆写项**；常见项如数据库 schema 或数据格式变更、部署结构与部署脚本、认证/授权/密钥、调度器与备份恢复、不可逆的数据迁移、依赖升级）。
- 拿不准时先按小任务做；做的过程中改动扩散到上述标准时就地升级：把已做与待做补写成方案文件，从第 2 步（交叉评审）继续。
- 用户说「直接改」只覆盖一般规模判定；命中高风险触发器或项目级入口文档「重大方案先过对抗性评审」条款的任务仍须评审，除非用户明确说「跳过评审」。用户说「走流程」则一律走。
- 判定结果动手前一句话告知用户（如「这个算大任务，走接力流程」），不等确认，直接开始。
