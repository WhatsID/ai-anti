# 登记台账

评审分诊里判为「登记」的意见落在这里：边界情况、低概率路径、理论完备性、只有将来规模变大才
成立的问题、「更稳妥的做法」。分诊判据以 `core/REVIEW_PRINCIPLES.md` R6 为唯一权威。

- **登记即算关闭**：条目进了本文件，当前需求就可以交付，不因它扩大范围、不因它再开评审轮；
  也允许永远不做。
- **只承载待做**：做完的条目从本文件移走，关闭说明写进提交信息与 `CHANGELOG.md`。

格式：每个需求一节，条目为
`- [ ] 严重度｜一句话 — 具体失败场景 / 什么条件下值得做｜来源`。

## 接力流程与评审通道

- [ ] 中｜**没有模块尺寸门禁的项目，只记行数不等于落实拆分** — 接力第 1 步要求标「当前行数 →
  改后预计」，但没配置门禁命令的项目里这只是自述。失败场景：方案如实写着「新组件：0 → 2500 行」
  → 评审与终审都无据可依 → 文件照旧一次写出两千多行。值得做的条件：第二个项目接入且出现单文件
  过千行。候选修法：正文加一条与门禁无关的兜底阈值，或要求未配置门禁的项目在方案里写放行理由。
  ｜来源：评审登记
- [ ] 低｜**没有自动检查能发现某一档评审通道悄悄坏了** — 失败场景：CLI 或端点升级改了协议 →
  跨模型通道陆续静默失效 → 高风险任务实际都只过同族档，汇报里却写着「已按阶梯降档」。值得做的
  条件：再出现一次「通道健康却被判不可用」。候选修法：每档加极小的连通性探针（一句话提问 + 断言
  `is_error:false`）。代价要先算：一次最小探针实测约 $0.25。｜来源：评审登记

## Codex→Claude 评审入口（claude-review / codex-relay）

- [ ] 低｜**plan 新增路径误用的现场提示** — 若更新指引后，另一设备新会话按原任务重跑仍将

- [ ] 低｜**二进制或超限材料不支持** — 含图片等文件的任务在准备期明确失败，不能删掉清单项后宣称

- [ ] 低｜**没有通用凭证内容扫描** — 配置文件或运行手册里内嵌的 token 可能不命中文件名拒绝规则；

- [ ] 中｜**Codex 方向没有自动降级** — 已支持显式 Claude/Qwen 通道选择，但评审失败时不会自动转其他通道
  或同族档；故障处理路径未做真实验证。｜来源：验证拆分
- [ ] 中｜**聚合上下文预算与自动时限估算** — 分块解决了单次 Read 上限，但接近 2 MiB 的必读正文
  仍可能超过模型上下文或默认总时间。出现已测范围之外的真实失败后再考虑模型相关预算。｜来源：方案评审
- [ ] 中｜**inventory 超长行** — 第一阶段返回超过 2000 字符的单行时，第二阶段准备明确失败，
  已耗第一阶段费用；不硬换行改写原清单。｜来源：方案评审
- [ ] 低｜**后生 inventory 的阶段空间预留** — 其加入可能令第二阶段超过 2 MiB 而失败（第二次调用
  前即拒绝）。真实频繁撞限时再评估预留配额与诊断提示。｜来源：方案评审
