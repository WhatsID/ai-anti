用 Codex CLI 接手实施。参数: $ARGUMENTS(方案文件路径,必填)。

**前置**:仅在 `CLAUDE.global.md` 容灾阶梯第②级触发时使用——implementer 已按退避重试仍中断满 3 次或阻塞超约 30 分钟。调用前主模型先用 `git status --short` + `git diff --stat` 整理「已完成/待完成」清单,连同任务外文件列表(须原样保留的并行改动)一并写入提示词。

主模型从实际加载的 `CLAUDE.global.md` 定位真实机制根，读取适用共享方法，
在下列提示词中填入 `DEBUGGING.md` / `TESTING.md` 的明确绝对路径。
接手者必须实际读取；必要路径缺失或不可读时报告，不从业务 cwd 猜机制源。

运行(Bash timeout 设 600000;任务大时可按模块分多次调用,每次给清晰的本次范围。调用形态见 **`core/CLI_DISCIPLINE.md`(外部 CLI 的调用纪律)**(四条,唯一权威);本文件原先自带的两条硬教训已于 2026-08-11 上收至该处,不在此重复——正是「只记在这一个模板里」导致同一个坑在 codex-review 上二次发作):

```
codex exec --sandbox workspace-write "你是实施工程师,接手一个因故中断的实施任务。严格按方案文件 <路径> 实施,先读方案全文与仓库的项目级入口文档(如 AGENTS.md / 项目 CLAUDE.md)。共享方法:<适用方法绝对路径列表>;先实际读取这些文件,诊断按 DEBUGGING、实施验证按 TESTING 留证;必要输入缺失时停下报告,不能假设继承正文。当前进度:<已完成清单>;本次需完成:<待完成清单>。硬边界:不对真实数据库执行迁移或写操作(单测一律用 fixture);不部署、不 push、不 commit;不改动以下任务外文件:<列表>;发现方案走不通立即停下报告,不要自行绕道。完成后输出:改动文件清单、验证命令及结果、偏离方案之处、遗留问题。" < /dev/null 2>&1
```

拿到输出后主模型必须:

- 用 `git diff` 核对 Codex 实际改动与其报告一致、未越界(任务外文件、禁改目录);
- **亲自做对抗性增量审查**(该任务不再调用 `/codex-review diff`——Codex 不能自己审自己);
- 复跑方案规定的全部验证;
- 最终汇报中标注「Codex 实施」及接手范围。
